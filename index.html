1 Executive Summary

We submit this proposal for the design, development and deployment of an AI-Based Secure Face Attendance & Liveness Verification System for Sreenidhi Institute of Science & Technology (SNIST), addressing proxy attendance, photo/video replay, poor lighting, pose variation, appearance drift and absent audit trails — in alignment with the DPDP Act, 2023.

Project Value: ₹6,60,000 (+GST) · Delivery: phased development → pilot → UAT → deployment → handover · Support: 3 months · Contract: Section 20 terms + Annexes A–G upon execution.

2 Background & Problem Statement

Security gap
Proxy & spoof attendance
Photos, phone screens, recorded video used to defeat naive systems.
Quality issues
Environment sensitivity
Low light, backlight, blur and angle cause false rejections.
Drift problem
Appearance change
Beard, hairstyle, glasses, weight changes degrade single-template matching.
Operational gap
No audit trail
Weak quality gates and no verifiable decision history.

The proposed solution reduces these risks through layered verification rather than a single match score.

5 Detailed Scope of Work

5.1 Requirements & Design

  • Stakeholder workshops to finalize workflows; roles: Student, Faculty, Administrator, Super Admin.
  • Sessions, courses, batches, time windows, verification rules; architecture & deployment plan.

5.2 Enrollment

  • DPDP-compliant consent capture (incl. parental consent workflow for minors per Annex C).
  • Guided face capture; embeddings/templates stored (raw images deleted post-extraction unless opted); multi-template; admin approval workflow.

5.3 Attendance Verification

  • QR/session-token capture; 2–3 s video; best-frame selection; cosine matching; Accept / Reject / Step-up decision engine.

5.4 Liveness & Anti-Spoofing

  • Passive texture/frequency checks; temporal multi-frame checks; blink, head-motion, color-flash challenges; per-session randomness; suspicious-attempt flagging.
Note: The system significantly reduces common spoofing (prints, simple replays, screen replay). No system guarantees absolute protection against advanced attacks, deepfakes, high-end masks or injection without specialized hardware or certified services.

5.5 Quality, Pose & Occlusion

  • 106-point landmarks; yaw/pitch/roll; Laplacian blur; brightness; face size; backlight; occlusion (mask/hand/scarf/glasses); live guidance messages.

5.6 Appearance Drift

  • Multi-template gallery; rolling updates gated by quality+liveness; grey-zone step-up; re-enrollment recommendations; unsafe-update protection.

5.7 Dashboard & Reports

  • Dark-themed role-based dashboard; live monitoring; verification logs with reason codes; exception review; reports by date/course/batch/student/session; CSV/Excel/PDF export.

8 Technical Approach

8.1 Capture pipeline

  1. Secure QR/session-token entry.
  2. 2–3 s video capture.
  3. Per-frame quality/pose/liveness analysis.
  4. Best-frame selection.
  5. Embedding generation and gallery match.

8.2 Decision logic

ConditionActionPurpose
Low quality frameRequest retakePrevent mismatch from blur/light/pose.
Low liveness scoreReject or step-up challengeDefeat photo/video spoofing.
Match > 0.75AcceptNormal verification.
Match 0.55–0.75Step-up / manual reviewHandle drift safely.
Match < 0.55RejectPrevent proxy attendance.

Thresholds are initial values; final operating points tuned during pilot against Annex B targets.

  • Explicit consent with purpose statement; verifiable parental consent for minors (ss.9–10) before enrollment (Section 20.16).

  • Data Fiduciary = Institution; Developer acts only as processor during development/support (Annex C).
  • Grievance process: institution-owned; Developer supplies grievance-workflow template in documentation.
  • Localization: India-default storage; any foreign hosting elected by Institution documented per Section 20.17.

9.2 Security controls

  • AES-256 at rest; TLS 1.3 in transit; RBAC least privilege; tamper-evident audit logs; short-lived JWTs; Pydantic schema validation on all endpoints.
Certification note: formal third-party certification (iBeta, ISO audits) is NOT in scope; pursuable separately.
